# 普通 admin 角色**可以**调用的 admin 读路由（显式登记表）。
#
# 与 `admin_rbac_write_allowlist.txt` 同一套断言（`admin_rbac_tests`），但目的不同：
# 写面那张表防的是「普通 admin 悄悄获得破坏能力」，这张表防的是「**新读端点悄悄开始
# 输出数据**」——读面没有"收紧到 super_admin"这个选项，因为读本来就是审核工作的主体。
# 所以这里不判"该不该给"，只记录"现在给了哪些"，让每一次增加都成为一次显式决定。
#
# 同一条判定的两个已知副作用（详见 docs/audit/ADMIN_RBAC_SURFACE_2026-10-21.md §9）：
#   · 前缀匹配**不认结尾斜杠**：`/reports/` 覆盖 `/reports/{id}` 却不覆盖 `/reports`，
#     于是"能取单条、不能列"这种自相矛盾会以登记项的形式暴露出来；
#   · 路径别名拿到不同判定（`quarantine_media/{id}/changes` vs `media/quarantine_changes`）。
#
# 格式：`<METHOD> <path>`，`#` 开头为注释。路径用 ROUTE_HANDLERS.json 的原样形式。
# 变更规则：新增读端点 ⇒ 要么登记在这里，要么加进 `is_super_admin_only_endpoint`。
