# 普通 admin 角色**可以**调用的 admin 写路由（显式登记表）。
#
# 为什么需要这份清单：`is_role_allowed("admin", …)` 的允许面是一条按前缀的 OR 链
# （`/_synapse/admin/v1/users`、`/rooms`、`/media` …），黑名单只从里面挖了 11 个洞。
# 于是**任何新增的、落在这些前缀下的写端点都会自动对普通 admin 开放**，没有任何
# 东西会提醒你。本清单把它变成显式声明：`admin_rbac_tests` 断言
# 「普通 admin 可执行的写路由」与「本文件」**双向相等** ——
#   · 新增端点落进前缀但没登记 ⇒ 测试红；
#   · 登记了但已不再可执行（规则收紧/路由删除）⇒ 测试红。
#
# 登记一条之前先问：这个写操作给普通 admin 合理吗？不合理就把它加进
# `is_super_admin_only_endpoint`，而不是登记到这里。
#
# 格式：`<METHOD> <path>`，`#` 开头为注释。路径用 ROUTE_HANDLERS.json 的原样形式。
