## 二、数据模型问题

### P1-1: room_summaries.member_count 派生字段无同步机制

**严重度**: 🟠 P1
**类别**: 数据完整性
**测量证据**:
```
文件: migrations/00000000_unified_schema_v10.sql

行 384-386:  member_count BIGINT DEFAULT 0,
             joined_member_count BIGINT DEFAULT 0,
             invited_member_count BIGINT DEFAULT 0,

# Rust 代码分析
synapse-storage/src/room/mod.rs:667:
    joined_member_count = joined_member_count + 1,  -- 应用层自增

synapse-storage/src/room/admin.rs:231:
    joined_member_count = joined_member_count + 1,

synapse-storage/src/room/admin.rs:253:
    joined_member_count = GREATEST(joined_member_count - 1, 0),

# 问题：没有触发器强制同步
# 没有触发器强制 member_count = (SELECT COUNT(*) FROM room_memberships WHERE room_id = ... AND membership = 'join')
```

**影响范围**:
1. **数据漂移风险**: 如果应用层更新失败（如网络错误、超时），`joined_member_count` 与实际 `room_memberships` 行数不同步。
2. **并发竞态**: 多个 worker 同时更新时，SQL `joined_member_count = joined_member_count + 1` 可能丢失更新。
3. **物化视图依赖**: `rooms_summaries_mv`（行 4132-4208）使用 `COUNT(*)` 重新计算，`room_summaries` 的缓存值可能与之矛盾。

**优化建议**:
```sql
-- 方案 1: 添加触发器强制同步
CREATE OR REPLACE FUNCTION sync_room_member_count()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' AND NEW.membership = 'join' THEN
        UPDATE room_summaries
        SET joined_member_count = joined_member_count + 1
        WHERE room_id = NEW.room_id;
    ELSIF TG_OP = 'DELETE' AND OLD.membership = 'join' THEN
        UPDATE room_summaries
        SET joined_member_count = GREATEST(joined_member_count - 1, 0)
        WHERE room_id = OLD.room_id;
    ELSIF TG_OP = 'UPDATE' AND OLD.membership != NEW.membership THEN
        IF OLD.membership = 'join' THEN
            UPDATE room_summaries
            SET joined_member_count = GREATEST(joined_member_count - 1, 0)
            WHERE room_id = NEW.room_id;
        ELSIF NEW.membership = 'join' THEN
            UPDATE room_summaries
            SET joined_member_count = joined_member_count + 1
            WHERE room_id = NEW.room_id;
        END IF;
    END IF;
    RETURN COALESCE(NEW, OLD);
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_sync_member_count
AFTER INSERT OR UPDATE OR DELETE ON room_memberships
FOR EACH ROW EXECUTE FUNCTION sync_room_member_count();

-- 方案 2: 移除冗余字段，完全依赖物化视图查询
```

**类别**: 数据完整性


**影响范围**:
1. 无效 ID 可能写入数据库，导致后续签名验证、 federation 处理失败。

```sql
    CHECK (user_id ~ '^[A-Za-z0-9._=/-]+@[A-Za-z0-9._=-]+$');

-- room_id 格式: !room_id:servername
ALTER TABLE rooms ADD CONSTRAINT ck_rooms_room_id_format
    CHECK (room_id ~ '^![A-Za-z0-9._=/-]+@[A-Za-z0-9._=-]+$');

-- event_id 格式: $random_base64
ALTER TABLE events ADD CONSTRAINT ck_events_event_id_format
    CHECK (event_id ~ '^\$[A-Za-z0-9_-]+$');

-- 注意：CHECK 约束在大量数据写入时可能产生性能开销
-- 建议仅在数据入口层（Rust 代码）做格式验证
```

```
    event_type TEXT NOT NULL,
    sender TEXT NOT NULL,
```

```sql
    ...
    PRIMARY KEY (event_id, room_id)

-- 创建 64 个分区
CREATE TABLE events_p0 PARTITION OF events FOR VALUES WITH (MODULUS 64, REMAINDER 0);
-- ... (创建 events_p1 到 events_p63)

-- 方案 2: 按时间范围分区（适用于时间范围查询优化）
CREATE TABLE events (
    event_id TEXT NOT NULL,
    room_id TEXT NOT NULL,
    ...
    PRIMARY KEY (event_id, origin_server_ts)
) PARTITION BY RANGE (origin_server_ts);

CREATE TABLE events_2026_q1 PARTITION OF events
    FOR VALUES FROM (0) TO (1719792000000);  -- 2026-06-01
CREATE TABLE events_2026_q2 PARTITION OF events
    FOR VALUES FROM (1719792000000) TO (1735680000000);  -- 2026-07-01
-- ...
```

```sql
CREATE OR REPLACE FUNCTION cleanup_old_logs(retention_days INTEGER DEFAULT 90)
RETURNS void AS $$
BEGIN
    -- 清理 e2ee_audit_log
    DELETE FROM e2ee_audit_log
    WHERE created_ts < EXTRACT(EPOCH FROM clock_timestamp()) * 1000 - (retention_days * 24 * 60 * 60 * 1000)::BIGINT;

    WHERE origin_server_ts < EXTRACT(EPOCH FROM clock_timestamp()) * 1000 - (retention_days * 24 * 60 * 60 * 1000)::BIGINT;
```

## 十、重部署窗口行动指南（2026-08-31 项目状态）

### 10.1 项目当前状态

- **未发布运行**：数据库可任意重置
- **可停机迁移**：不需要 24/7 在线服务承诺
- **清理重部署**：用户明确允许优化完成后清除原数据重新部署

这给了一个**非常宝贵的优化窗口**：可以大胆做**不可逆优化**，无需考虑向后兼容、零停机约束、回滚脚本。

### 10.2 重部署窗口的优化原则

| 传统原则（生产环境） | 重部署窗口原则 |
|---|---|
| 零停机 | 可停机数分钟 |
| 必须回滚脚本 | 不需要 |
| 不破坏向后兼容 | 可改列名、改类型、改默认值 |
| 增量迁移必须 | 重建 schema v11 内联所有变更 |
| 加 NOT VALID 后 VALIDATE | 直接 ALTER TABLE |
| 保留 undo 文件 | 全部删除 |

### 10.3 利用窗口应做的**破坏性但更好的**优化

#### 🔴 P0-1 events 表分区策略（重部署窗口优先）

**建议**：用 v11 schema 直接按 HASH(room_id) 建 64 分区。

```sql
-- v11 schema 内联（重部署窗口不需要 NOT VALID 路径）
CREATE TABLE events (
    event_id TEXT NOT NULL,
    room_id TEXT NOT NULL,
    ...
    PRIMARY KEY (event_id, room_id)
) PARTITION BY HASH (room_id);

-- 自动建分区函数
CREATE OR REPLACE FUNCTION auto_create_events_partitions(modulus INT)
RETURNS void LANGUAGE plpgsql AS $$
DECLARE
    i INT;
BEGIN
    FOR i IN 0..modulus-1 LOOP
        EXECUTE format(
            'CREATE TABLE IF NOT EXISTS events_p%s PARTITION OF events FOR VALUES WITH (MODULUS %s, REMAINDER %s)',
            i, modulus, i
        );
    END LOOP;
END;
$$;

SELECT auto_create_events_partitions(64);
```
