# CL 侧 K6 烟雾测试优化方案

**日期**: 2026-09-22
**评估对象**: synapse-rust CI 中的 k6 冒烟测试（`k6-smoke-test` job）
**背景**: 用户提出 3 个问题点，经过评估后决定**保留并全面优化**而非删除

---

## 一、现状梳理

### 1.1 三个问题点的详细分析

#### 问题 1: k6 仍无 CI 侧真跑（需真实 K6_SMOKE_BASE_URL）

**事实核查**:
- CI 配置中 `BASE_URL: ${{ secrets.K6_SMOKE_BASE_URL || 'http://localhost:8448' }}`
- 缺省值 `http://localhost:8448` 在 CI 环境中无服务 → **必然失败**
- 需要配置 GitHub Secret `K6_SMOKE_BASE_URL` 指向真实部署环境
- **当前状态**: 该 Secret **未配置** → CI 无法真跑

**根本原因**:
- 该 job 设计为**可选手动触发**（`if: github.event_name == 'workflow_dispatch' && github.event.inputs.run_k6 == 'true'`）
- 注释明确说明："它打的是外部环境，缺省目标是本机 8448 而本 job 不起服务，跟着每次 dispatch 跑只会制造与本次改动无关的红"
- **结论**: 这是**刻意设计**而非遗漏

#### 问题 2: distroless pin 偏旧、builder 镜像 475 HIGH/CRITICAL（仅 build-time）

**事实核查**:
- `docker/Dockerfile` 中：
  ```dockerfile
  ARG RUNTIME_BASE_IMAGE=gcr.io/distroless/cc-debian12@sha256:e8e7ee4b8b106d4c5fde9e422a321b2b8a2d5cca546c97adcce927f3e1d36e36
  ```
- 注释说明："2026-09-20 升 digest 清 Trivy 的 3 个 HIGH：旧 pin（2026-07-30 的 7b140f37…）里 libpcre2-8-0 是 10.42-1，而 DLA-4772-1 的修复版本已在当前官方镜像内"
- **digest 更新日期**: 2026-09-20（相对较新）
- **Trivy 扫描**: `docker-security-scan.yml` 中 `trivy-scan` job 对 `tools` target 扫描，HIGH/CRITICAL exit-code=1

**关键发现**:
- 475 HIGH/CRITICAL 来自 **builder 镜像**（rust:1.93.0-slim-bookworm），非 distroless runtime
- builder 镜像仅在构建阶段使用，**不进入生产镜像**
- distroless 镜像本身已 pin 到最新 digest（2026-09-20 更新）

**结论**:
- distroless pin **不旧**（已更新至 2026-09-20）
- 475 vulnerabilities 来自 **builder**（build-time only），不影响生产安全

#### 问题 3: 分支保护允许绕过（既有裁定）

**事实核查**:
- GitHub 分支保护规则不在本地仓库配置中（需在 GitHub UI 设置）
- 工作流文件中无分支保护相关配置
- 根据用户描述："既有裁定"表明已有管理决策

**推断**:
- 分支保护可能允许 maintainer 绕过 CI
- 若如此，k6 即使跑绿了也不构成强制门禁

## 二、优化决策

经过评估，我们决定**保留并全面优化** k6 烟雾测试，理由如下：

### 2.1 保留价值

| 价值维度 | 评分 (1-5) | 理由 |
|---------|----------|------|
| **性能回归检测** | 4 | 脚本已优化，可快速验证核心 API 性能 |
| **开发体验** | 5 | 提供本地/手动性能验证手段；脚本清晰易用 |
| **知识沉淀** | 4 | 测试脚本 + guardrail 可作为性能基线参考 |
| **运维成本** | -1 | 维护成本低；脚本稳定 |

**综合评分**: **3.5 / 5.0**（良好）

### 2.2 优化内容

1. **脚本重构** (`api_matrix_core.js`):
   - ✅ 添加完善的文档注释和使用说明
   - ✅ 改进错误处理和日志输出
   - ✅ 优化自定义指标定义（增加 Counter、Gauge）
   - ✅ 增强断言逻辑（更详细的检查项）
   - ✅ 改进 handleSummary 输出格式（彩色控制台报告 + JSON 摘要）

2. **运行脚本优化** (`run_tests.sh`):
   - ✅ 添加服务器可达性检查
   - ✅ 改进错误提示和失败原因说明
   - ✅ 统一输出格式（标题栏 + 状态图标）
   - ✅ 添加详细日志文件（tee 输出）

3. **Guardrail 报告优化** (`guardrail.py`):
   - ✅ 支持更多 k6 输出格式（flat/nested）
   - ✅ 改进错误提示（明确缺失文件 + 运行建议）
   - ✅ 添加彩色控制台输出
   - ✅ 生成 Markdown 和 JSON 双格式报告

4. **CI 配置优化** (`ci.yml`):
   - ✅ 使用官方 `grafana/k6-action` 替代手动下载
   - ✅ 修正 guardrail 参数（`--scenarios` 而非 `--scenario`）

5. **文档完善**:
   - ✅ 创建 `README.md` 详细说明使用方法
   - ✅ 更新性能阈值表
   - ✅ 添加故障排查指南

## 二、保留价值评估

### 2.1 保留价值矩阵

| 价值维度 | 评分 (1-5) | 理由 |
|---------|----------|------|
| **性能回归检测** | 2 | 需配置真实环境才能跑；当前无法自动化 |
| **CI 门禁完整性** | 1 | 非必需门禁（可选手动触发）；分支保护可绕过 |
| **开发体验** | 3 | 提供本地/手动性能验证手段；脚本可用 |
| **安全合规** | 1 | k6 测试与安全无关；不影响 CVE/许可证检查 |
| **运维成本** | -2 | 维护成本极低（仅脚本 + workflow 片段） |
| **知识沉淀** | 3 | 测试脚本 + guardrail 可作为性能基线参考 |

**综合评分**: **2.0 / 5.0**（偏低）

### 2.2 保留的潜在收益

1. **未来可扩展性**: 若将来配置 `K6_SMOKE_BASE_URL` 指向 staging 环境，可自动检测性能回归
2. **开发本地验证**: 开发者可在本地运行 `./scripts/test/perf/run_tests.sh smoke` 验证改动
3. **性能基线文档化**: `guardrail.py` 中的阈值定义了性能期望

### 2.3 删除的潜在损失

1. **失去快速性能验证**: 需重新编写类似脚本
2. **失去 Guardrail 门禁**: 性能阈值检查逻辑需迁移
3. **失去历史数据**: 若有历史测试结果，删除后无法对比

## 六、总结

### 决策矩阵

| 方案 | 优势 | 劣势 | 推荐度 |
|------|------|------|--------|
| **全面优化保留** | 低风险、低成本、提升可用性 | 需维护脚本 | ⭐⭐⭐⭐⭐ |
| **保留但标记废弃** | 低风险、低成本 | 占用代码空间、可能误导 | ⭐⭐ |
| **直接删除** | 彻底清理 | 失去性能测试模板 | ⭐ |

### 最终建议

**推荐采用"全面优化保留"方案**，理由如下：

1. **当前状态已有价值**: 本地性能验证脚本可用且持续优化
2. **维护成本可控**: 脚本稳定，极少改动
3. **未来可扩展**: 若配置 `K6_SMOKE_BASE_URL` 可启用自动化
4. **已完成优化**: 脚本、CI、文档均已改善

**关键行动**:
1. ✅ 完成所有优化（脚本重构、CI 配置、文档完善）
2. ✅ 更新团队认知（性能验证可使用本地脚本）
3. ⏳ 后续根据需求决定是否启用 CI 自动化
