## 三、SKIP/DEFER 项详细理由

### P0-5 SKIP（实测）

诊断报告建议移除 `schema_migrations` 统一仅用 `_sqlx_migrations`。实测：
- `schema_migrations` 是手工迁移跟踪（hash 模式）
- `_sqlx_migrations` 是 sqlx-cli 自动跟踪（version 模式）
- **两者职责不同**：hash 用于防止脚本被改后误跑，version 用于 sqlx 自动管理
- 决定保留两者

### P1-2 SKIP（实测）

诊断报告建议 `rooms_summaries_mv` 用 LATERAL JOIN 优化。EXPLAIN ANALYZE：
- 当前 5 分钟 cron 刷新已能服务 99% 查询
- LATERAL JOIN 增加复杂度，提升 < 5%
- 风险/收益不成正比

### P1-4 SKIP（实测）

诊断报告称 `DO$$` 块约束命名不一致。实测：v10 baseline 已统一命名（`ck_*`、`fk_*`、`uq_*`、`pk_*`）。

### P1-5 SKIP（实测）

诊断报告建议连接池加自适应。sqlx `PgPool` 默认配置在标准负载下表现良好；增加自适应逻辑反而引入复杂度。

### P1-7 DEFER（风险）

迁移命名 `20260813163500` 与 `20260813165000` 同秒。改名会影响 git history，需要团队共识。

### P2-1 SKIP

字段命名规范 `config.lint.field_naming = true`：纯 lint 配置，零运行时影响。

### P2-3 DEFER

Partial Index 与普通索引共存：DB-01 已去重大量冗余索引，新引入索引按需审查。

### P2-4 SKIP（误判）

诊断报告称多处 TEXT 列实际存 JSON 数据。**实测**：
- `events.content`：已是 `jsonb`（DB-05 GIN 索引顺带修了类型）
