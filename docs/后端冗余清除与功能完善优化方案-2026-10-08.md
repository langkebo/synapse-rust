## 0. 结论先行

1. **后端不存在未修复的 P0 缺陷**。契约门禁在当前 HEAD **全绿**（`check_route_contract.sh` EXIT=0，
   67 条守卫 + mutation 自证全过）。上一轮曾判"HEAD 契约门禁红"，**该判定已证伪**：
   `docs/` 缺同步的守卫修复已由 `2a411440b` 提交，且当时"守卫仍钉着 5 条已删路由"的结论是把

2. **冗余面收敛为 5 类、共 41 条路由 + 4 处代码/脚手架**，全部有机器可判的判据，无一条需要"猜"（§2）。
3. **功能完整性无风险项**：本轮新增的三处待删对象都有明确承接方或零消费者（§4）。
   唯一需要"先确认再删"的是 2 处**请求体兼容分支**（§2.5），列为待裁定而非直接删除。
4. **最大的结构性缺口是门禁盲区**（§2.4、§2.6）：`client` 前缀 ∩ `vendor` 孪生的死别名有 **6 条
   完全没进台账**，因为现行守卫只覆盖"整模块私有文件"，而它们落在混合模块里。
   **建议先补判据再删代码** —— 这样删除动作自带"先红后绿"的自证。
5. 建议 **6 个批次**，其中 B0/B1 为零风险，B2/B3 为路由面变化（须跨仓：后端 → SDK → Tjg），
   B4 为门禁补强，B5/B6 为收口（§3）。

   C6 反冗余的**四个批次全部**漏刷两份集成快照，
   `tests/integration/snapshots/route_ledger_{default,worker_enabled}.snapshot` 各残留 **12 条**

   `7779685e8`（C6 第一批）起连续四批为红，而 `check_route_contract.sh` **看不见**它。
   已修复并补上守卫（含变异自证）。这是方案 §5.1 那句"一个提交只重生成一半派生产物"
   的**又一次实例** —— 并且证明 §5.1 的清单本身当时也漏了这两份快照。
7. **第二条同类缺陷**（执行 R-02 时连带发现，见 §2.4b）：提取器的 `manifest oracle`
   **输入集合恒为空**（`manifest_routes()` 返回 0 条），所以守卫

### 2.4b R-09（P1，执行 R-02 时发现并已修复）空转的 manifest oracle —— 一条恒真的门禁

- **位置**：`scripts/contract/extract_registered.py` 的 `manifest_routes()`（原 2476-2487）、
  驱动段对账（原 2692-2731）、strict 分支的 `only_manifest`，
  以及 `test_extract_registered.py::check_oracles` 的第一条断言。
- **判据**：一条门禁的**输入集合为空**时，`A ⊆ B` 恒真 ⇒ 它永远绿。
  实测：`manifest_routes()` 只收集到 **1** 个函数（`derived_routes.rs::derived_route_manifest`），
  求值结果 **0 条**；提取器自己也打印 `manifest-declared tuples: 0`，
  而守卫仍报 `ok every manifest-declared route is derived (manifest oracle)`。
- **复现**：

  ```bash
  cd scripts/contract && python3 - <<'PY'
  import importlib.util
  s = importlib.util.spec_from_file_location('ex', 'extract_registered.py')
  ex = importlib.util.module_from_spec(s); s.loader.exec_module(ex)
  res = ex.Resolver(ex.load_sources())
  print([(f, n) for (f, n, _b) in res.fn_all if 'manifest' in n])
  print('manifest_routes():', len(res.manifest_routes()))
  PY
  # → [('derived_routes.rs', 'derived_route_manifest')] / 0
  ```

- **根因**：手写 `*_route_manifest()` 已全部迁入 `#[cfg(test)] mod tests`（被
  `strip_test_mods` 切除），其余被生成的 `derived_route_manifest` 取代
  （见 `synapse-web/src/routes/derived_routes.rs` 头注："replaces the ~120 hand-copied
  `*_route_manifest()` helpers"）。历史值可对照：2026-09-14 的归档文档记 `manifest-declared 1077`。
- **危害**：它把"**零覆盖**"报告成"**通过**"（铁律 8 直指的情形），并让
  `extract_registered.py` 的文档字符串与 `gen_contract_doc.py` 的正文
  都声称"两份**独立**事实来源已对账"。删掉后守卫数 75 → **74**。
- **保留的那条 oracle 是真的**：`tests/unit/fixtures/ledger_export{,_sdk}/*.json` 由
  **Rust 二进制**导出（`tests/unit/ledger_export_tests.rs` 的 `--output=`），
  与本解析器是两套实现；它当前 0 missing，仍然有效。
- **处置（已完成）**：删 `manifest_routes()` 与其对账段、strict 分支、守卫断言、
  module docstring 的相应描述；`gen_contract_doc.py` 与 `ROUTE_CONTRACT.md` 的
  "两份**独立**事实来源"改为准确表述。

### 2.8b R-11（P1，执行中发现）门禁盲区：`check_sdk_route_coverage.py` **前缀盲**

**现象**：本批把 29 条路由从 `/_matrix/client/{v1,v3}` 迁到 `/_matrix/vendor/v1` 后，
该门禁仍报 `✅ 所有 SDK 调用的端点都在 ledger 中（且 method 一致）` —— 而 SDK 侧**仍在打旧前缀**，
运行时会 404。即：**后端改前缀不会被这道门禁发现**。

**根因（两条，缺一不可）**：
1. 主判据**前缀无关**：`path_match(relative, p)` 只要求 SDK 的**相对路径**能对齐到某条 ledger 路径的**尾部**
   （`check_sdk_route_coverage.py:328-329`）⇒ `/_matrix/client/v3/create_dm` 与
   `/_matrix/vendor/v1/create_dm` 产生**同一组**候选。
2. 收紧判据自废：解析出 `full` 后本应只保留 `path_match(full, p)` 的候选，但写法是
   `[... if path_match(full, p)] or candidates`（`:349-352`）——**`or candidates` 兜底**让
   `full` 不认识任何路径时**静默回退**到前缀无关候选集 ⇒ 前缀事实上从未生效。

**机器取证**（可直接复跑）：

```bash
python3 - <<'EOF'
import importlib.util, pathlib, json
spec = importlib.util.spec_from_file_location('cov', 'scripts/contract/check_sdk_route_coverage.py')
cov = importlib.util.module_from_spec(spec); spec.loader.exec_module(cov)
backend = [(e['method'], e['path']) for e in json.load(open('tests/unit/fixtures/ledger_export_sdk/all.json'))['entries']]
sdk = pathlib.Path('../matrix-js-sdk')
cov.methods = cov.load_methods(sdk); cov.prefixes = cov.load_prefixes(sdk)
sites = cov.collect_sites(sdk)
print('站点', len(sites), '| 解出 full', sum(1 for s in sites if s['full']))
for s in sites:
    if s['full'] and not any(cov.path_match(s['full'], p) for _, p in backend):
        print('  未被任何 ledger 路径承接:', s['file'], s['line'], s['method'], s['full'])
EOF
```

实测：**115** 个站点中仅 **29** 个解出 `full`，其中 **3** 个 `full` 在后端**根本不存在**，门禁却报绿：

- `src/reporting/index.ts:93` `PUT /_matrix/client/v3/rooms/$roomId/report/$eventId/score` ← **本批已迁**
- `src/reporting/index.ts:112` `GET /_matrix/client/v1/rooms/$roomId/report/$eventId/scanner_info` ← **本批已迁**
- `src/client-secure-backup-requests.ts:39` `/_matrix/vendor/v1/keys/backup/secure/$backupId/restore`
  ← **与本批无关**，疑似既有 SDK↔后端不一致，**待裁定**（另开条目）

**建议**：把 `or candidates` 换成"`full` 解出且不匹配任何路径 ⇒ 记 `uncovered`"（即**让前缀生效**），
并补一条变异自证（注入一条前缀被改的路由 ⇒ 必须红）。归入 Batch 4 的 G-01 家族。
⚠️ 修好后本批这 3 条会**立刻转红** —— 这正是它该有的行为（SDK 未迁完本来就该红）。
