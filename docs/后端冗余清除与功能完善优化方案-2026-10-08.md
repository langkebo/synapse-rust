## 0. 结论先行

1. **后端不存在未修复的 P0 缺陷**。契约门禁在当前 HEAD **全绿**（`check_route_contract.sh` EXIT=0，
   67 条守卫 + mutation 自证全过）。上一轮曾判"HEAD 契约门禁红"，**该判定已证伪**：
   `docs/` 缺同步的守卫修复已由 `2a411440b` 提交，且当时"守卫仍钉着 5 条已删路由"的结论是把

2. **冗余面收敛为 5 类、共 41 条路由 + 4 处代码/脚手架**，全部有机器可判的判据，无一条需要"猜"（§2）。
3. **功能完整性无风险项**：本轮新增的三处待删对象都有明确承接方或零消费者（§4）。
   唯一需要"先确认再删"的是 2 处**请求体兼容分支**（§2.5），列为待裁定而非直接删除。
4. **最大的结构性缺口是门禁盲区**（§2.4、§2.6）：`client` 前缀 ∩ `vendor` 孪生的死别名有 **6 条
   完全没进台账**，因为现行守卫只覆盖"整模块私有文件"，而它们落在混合模块里。
   **建议先补判据再删代码** —— 这样删除动作自带"先红后绿"的自证。
5. 建议 **6 个批次**，其中 B0/B1 为零风险，B2/B3 为路由面变化（须跨仓：后端 → SDK → Tjg），
   B4 为门禁补强，B5/B6 为收口（§3）。

   C6 反冗余的**四个批次全部**漏刷两份集成快照，

   的**又一次实例** —— 并且证明 §5.1 的清单本身当时也漏了这两份快照。

   **输入集合恒为空**（`manifest_routes()` 返回 0 条），所以守卫

### 2.4b R-09（P1，执行 R-02 时发现并已修复）空转的 manifest oracle —— 一条恒真的门禁

- **位置**：`scripts/contract/extract_registered.py` 的 `manifest_routes()`（原 2476-2487）、
  驱动段对账（原 2692-2731）、strict 分支的 `only_manifest`，
  以及 `test_extract_registered.py::check_oracles` 的第一条断言。
- **判据**：一条门禁的**输入集合为空**时，`A ⊆ B` 恒真 ⇒ 它永远绿。
  实测：`manifest_routes()` 只收集到 **1** 个函数（`derived_routes.rs::derived_route_manifest`），
  求值结果 **0 条**；提取器自己也打印 `manifest-declared tuples: 0`，
  而守卫仍报 `ok every manifest-declared route is derived (manifest oracle)`。
- **复现**：

  ```bash
  cd scripts/contract && python3 - <<'PY'
  import importlib.util
  s = importlib.util.spec_from_file_location('ex', 'extract_registered.py')
  ex = importlib.util.module_from_spec(s); s.loader.exec_module(ex)
  res = ex.Resolver(ex.load_sources())
  print([(f, n) for (f, n, _b) in res.fn_all if 'manifest' in n])
  print('manifest_routes():', len(res.manifest_routes()))
  PY
  # → [('derived_routes.rs', 'derived_route_manifest')] / 0
  ```

- **根因**：手写 `*_route_manifest()` 已全部迁入 `#[cfg(test)] mod tests`（被
  `strip_test_mods` 切除），其余被生成的 `derived_route_manifest` 取代
  （见 `synapse-web/src/routes/derived_routes.rs` 头注："replaces the ~120 hand-copied
  `*_route_manifest()` helpers"）。历史值可对照：2026-09-14 的归档文档记 `manifest-declared 1077`。
- **危害**：它把"**零覆盖**"报告成"**通过**"（铁律 8 直指的情形），并让
  `extract_registered.py` 的文档字符串与 `gen_contract_doc.py` 的正文
  都声称"两份**独立**事实来源已对账"。删掉后守卫数 75 → **74**。
- **保留的那条 oracle 是真的**：`tests/unit/fixtures/ledger_export{,_sdk}/*.json` 由
  **Rust 二进制**导出（`tests/unit/ledger_export_tests.rs` 的 `--output=`），
  与本解析器是两套实现；它当前 0 missing，仍然有效。
- **处置（已完成）**：删 `manifest_routes()` 与其对账段、strict 分支、守卫断言、
  module docstring 的相应描述；`gen_contract_doc.py` 与 `ROUTE_CONTRACT.md` 的
  "两份**独立**事实来源"改为准确表述。
