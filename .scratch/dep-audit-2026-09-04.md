### H2. `rsa 0.9.10` Marvin Attack（RUSTSEC-2023-0071）

| 字段 | 值 |
|------|---|
| 现状 | `src/services/builtin_oidc_provider.rs` 用 `Algorithm::RS256`（`jsonwebtoken`）+ `rsa::pkcs1v15::SigningKey::<Sha256>`，6 处 rsa API 引用 |
| 风险边界 | 仅做 SHA256withRSA 签名（jwt.encode + kid header + RS256 PKCS#1 v1.5 padding）；无 `Oaep::decrypt` / `pkcs1v15::decrypt` 等解密路径 |

| Review-by | 2026-06-30（已过期）→ **2026-12-31 续期** |

**已调查结论**：
- builtin_oidc_provider 完全 RS256 化，密钥管理（PEM load/生成/编码）为 RSA 专用

### M2. `deny.toml` 配置澄清（已落地 ✅）

`rsproxy.cn` 在 Cargo.lock 中"未命中"≠"未使用"。实际场景：

- **逻辑源**（lockfile 记录）：所有 crate `source = "registry+https://github.com/rust-lang/crates.io-index"`
- **物理下载**：`.cargo/config.toml` 配置 `[source.crates-io] replace-with = "rsproxy-sparse"`
  → 实际下载走 `sparse+https://rsproxy.cn/index/` 镜像（中国大陆加速）
- rsproxy 仅是下载代理，**不影响 lockfile 内容**、**不绕过 checksum**

**已落地**：`deny.toml` [sources] 注释重写，明确"逻辑源 vs 物理下载源"两层模型（commit pending）。rsproxy 白名单**保留**——移除会导致中国大陆构建失败。

> 教训：审计 "rsproxy 0 crate 命中" 的结论容易误读。lockfile 记录的是逻辑源，物理下载源在 .cargo/config.toml。两层概念在 deny.toml 中应分开说明。
