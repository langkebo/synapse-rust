# 08: 滑动同步的缓存失效改为批量删除

**What to build:** 滑动同步在连接状态变更时要失效一批缓存键：三个前缀下的所有键，加四个精确键。当前是对每个键单独发一次删除并串行等待，键数量随 list/room 增长，房间多的账号单次失效可能有几十次往返。本票把删除合并为一次批量操作。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**审计条目：** #7（🟢 Low）— sliding sync 缓存失效串行删除 N 个 key

- [ ] 缓存层提供批量删除能力（本地层与 Redis 层都要清，且 Redis 侧合并为单次请求）
- [ ] 滑动同步的失效逻辑改用批量删除，往返次数不再随键数量线性增长
- [ ] 精确键的删除仍然同时清本地层与 Redis 层（不得退化成只发 Redis DEL 而留下陈旧本地副本）
- [ ] 「新增缓存键必须登记」的守卫测试仍然通过，键清单不被本票改动
- [ ] 相关 crate 的既有测试全绿，`cargo clippy -- -D warnings` 无告警
