## FederationConfig 手写 impl Default（commit b5cd3e41）

FederationConfig 有 39 个字段，`#[derive(Default)]` 把所有字段默认成零值（`port=0`、`enabled=false`、`server_name=""`），但业务上有意义的默认值都走 `default_xxx()` 助手函数（serde 默认值）。这导致：
- `FederationConfig::default()` 不可用（返回一堆零值）
- 加字段时测试 literals 必须加 `..Default::default()` 才能编译

改成手写 `impl Default for FederationConfig`：39 个字段全部显式写出，路由到 `default_xxx()` 助手函数。结果 `FederationConfig::default()` 与 serde 解析缺省 YAML 时一致，加新字段只需在 impl 内补一行 + 一个 helper。

不需要改 `TrustedKeyServer`（Vec::default() 不依赖 T: Default）。

验证：fmt + clippy 全过；821 lib 测试全过。

## B-3 missing_docs 棘轮法（commits 456ce2c9 + d1264a25）

仓库现状：7 个 crate 都用 `#![allow(missing_docs)]`，累积几百个 warning。直接打开 `-W missing_docs` 会立刻让 CI 爆红——长红 CI 等于无 CI。

棘轮策略：
1. **存量不动**：保持 crate 级 `allow`，所有既有 warning 不动
2. **增量卡死**：
   - 新文件：所有 pub 项必须有 `///` doc
   - 修改文件：仅 diff 中新增的 pub 行必须有 doc（已有 pub 不管）
3. **debt baseline 锁存量**：scripts/.missing-docs-baseline 记录当前 debt = 6（crate 级 / module 级 warning），数字减少必须失败 → 收紧 baseline；数字增加也失败

实现：
- `scripts/check_missing_docs_ratchet.py`：Python 脚本，扫描 `git diff` 用 `regex` 找 `pub fn/struct/enum/trait/...` 然后查上方 30 行有无 `///`
- `scripts/check_missing_docs_ratchet.sh`：shell wrapper
- `scripts/.missing-docs-baseline`：6
- `.github/workflows/ci.yml`：在 clippy 之后加 step 调用脚本

脚本逻辑细节：
- `check_pub_has_doc(file, pub_line, lines)`：向上扫描 30 行找 `///` 或 `/**`，遇到非空非属性非 doc 即失败
- `scan_file_for_pub(file)`：新增文件全量扫描
- `scan_diff_for_new_pub(file, base)`：修改文件只扫 diff 中新增的 pub 行（用 git diff hunk header `@@ -X,Y +A,B @@` 定位）
- `count_total_debt()`：对 7 个 crate 分别用 `cargo clippy -A missing_docs -D missing_docs`（抵消 crate 级 allow）累加

### 经验
- B2-TODO 风格棘轮法：CI 卡增量、baseline 锁存量、debt 减少必须收紧，三件套缺一不可
- `git diff --diff-filter=A` 只看新增文件；`--diff-filter=M` 看修改文件（脚本需要分开处理）
- `git diff @@ -X,Y +A,B @@` hunk header 中 `+A` 是新增段在新文件的起始行号，逐行 +1 跟踪新增行
- clippy `-A missing_docs -D missing_docs` 可以抵消 crate 级 `allow(missing_docs)` 强制 report（用于 baseline 计数）

## B-1.3 ✅ upgrade_room 并发邀请 former members（commit 8b5891f8）

问题：`upgrade_room()` 曾对所有 former members 串行 `invite_user()`。远程用户走联邦 HTTP 调用，大房间（100+ 成员）墙钟随成员数线性增长。

三段式并发管道：
- Phase 1：按 `is_remote_user()` 划分 locals / remotes（同步字符串解析，无副作用）
- Phase 2：locals 走 `futures::future::join_all`（本地 DB 并发，warn-only）
- Phase 3：remotes 走 `stream::iter(...).buffer_unordered(16)`（联邦并发上限 16，对齐 Synapse `join_max_concurrency`）

设计决策：
- Phase 2/3 均为 warn-only 而非 fail-fast：单邀请失败不中断整次升级
- `FEDERATION_INVITE_CONCURRENCY = 16` 硬编码（与本仓 `push/service.rs` `MAX_CONCURRENT_SENDS = 8` 等本地常量风格一致）
