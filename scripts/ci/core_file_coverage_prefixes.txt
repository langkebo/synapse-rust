# Core security-critical / high-traffic path prefixes for
# `scripts/check_file_coverage.py --core-files` (--core-threshold applies to them).
#
# Prefixes are matched against the key produced by `_normalize_path()`, which is
# CRATE-QUALIFIED:
#     synapse-services/src/auth/mod.rs -> synapse-services/auth/mod.rs
#     src/lib.rs                       -> src/lib.rs        (root crate)
#     tests/integration/mod.rs         -> tests/integration/mod.rs
#
# These prefixes used to be crate-agnostic (`auth/`, `e2ee/`, `event/`) because
# the normalizer stripped everything up to the first `src/`. That made each
# prefix match unintended crates as well — measured on the real tree:
#     `auth/`  matched synapse-services/src/auth  AND synapse-storage/src/auth
#     `e2ee/`  matched src/e2ee                   AND synapse-storage/src/e2ee
#     `event/` matched synapse-services/src/event AND synapse-storage/src/event
# (`crypto.rs` / `security.rs` / `token.rs` / `signing.rs` were ambiguous by
# basename.) The extra matches below are kept EXPLICITLY so this rewrite does not
# silently narrow the gate: the set of files the core threshold applies to is
# unchanged (verified by comparing old-vs-new match sets over every .rs file).
#
# Historically this list lived at `artifacts/core_file_list.txt`, which is
# .gitignore'd and generated by nothing -> in CI the file was always missing,
# `load_core_prefixes()` returned [], and the core-coverage threshold silently
# applied to zero files. It is authored config, not a derived artifact, so it
# now lives under version control. `check_file_coverage.py` fails loudly when a
# prefix here matches no file on disk, so it cannot rot again.
#
# Original 13 areas (2026-06-03 audit): services/auth, services/sync_service,
# services/room_service, services/container, services/refresh_token_service,
# e2ee, web/routes, web/middleware, storage/event, federation, crypto, security.
