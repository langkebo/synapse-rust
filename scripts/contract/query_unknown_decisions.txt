# Query-unknown policy registry
#
# Purpose
#   Single source of truth for the sidecar field `query_unknown` in
#   docs/synapse-rust/ROUTE_HANDLERS.json. Every route whose handler extracts a
#   typed `Query<..>` must carry exactly one line here, so the decision is
#   reviewed once instead of being re-derived from whatever serde attributes
#   happen to exist today.
#
#   Enforced by scripts/contract/check_query_unknown_decisions.py:
#     - coverage      every typed route in the sidecar has exactly one line
#     - consistency   decision "reject" <=> sidecar query_unknown == "reject"
#     - staleness     a line whose route is gone or no longer typed is RED
#     - vocabulary    reason must come from the closed set documented below
#
# Columns (tab separated)
#   method  path  decision  reason  struct  note
#
# Decisions
#   reject   unknown query parameter -> 400 (axum/serde rejection)
#   ignore   unknown query parameter -> silently dropped, request proceeds
#
# Reason vocabulary
#   already-deny            struct already carried #[serde(deny_unknown_fields)]
#                           before this registry existed
#   internal-strict         project-private endpoint (worker / internal admin
#                           trigger); no external client, so extra params are a
#                           caller bug and are rejected
#   matrix-cs-ignore        Matrix client-server API: the spec requires unknown
#                           query parameters to be ignored
#   vendor-open             _matrix/vendor extension: kept open so already
#                           deployed clients survive a server-side rollout
#   federation-forward-compat  server-server API: older/newer peers must be able
#                           to send parameters this build does not know
#   upstream-admin-parity   _synapse/admin endpoint mirroring upstream Synapse,
#                           which ignores unknown parameters
#   external-idp            parameter set dictated by an external CAS identity
#                           provider's redirect, not by us
#   shared-struct           struct is also used by a client-facing route, so it
#                           cannot be tightened without changing the client API
#   manual-deserialize      struct has a hand-written Deserialize impl; a serde
#                           attribute would be dead code and make the sidecar lie
#   compat-alias            struct deliberately stays open because of a
#                           documented back-compatibility alias
#
# Regenerate the skeleton after an intentional policy change:
#   python3 scripts/contract/check_query_unknown_decisions.py --print
# then edit the affected lines by hand. Do not copy numbers into prose.
