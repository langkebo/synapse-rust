# Ledger route annotations — field overrides the source-based extraction
# cannot produce.
#
# Format: `METHOD PATH<TAB>key=value [key=value ...]`
#   * Lines starting with `#` are comments; blank lines are skipped.
#   * `METHOD PATH` is separated by whitespace (paths contain no spaces, so the
#     address is always exactly two tokens).
#   * EXACTLY one tab separates the address from the annotation block. Two or
#     more tabs produce a parse error so a stray tab in a path cannot silently
#     become (part of) an annotation.
#   * `key=value` pairs are space-separated and additive. Unknown keys are
#     rejected: a typo in an annotation name turns the suite RED rather than
#     becoming a silent no-op.
#
# Why this table exists
# ---------------------
# `RouteEntry` carries builder fields that describe *author intent*, not just
# the `(method, path)` tuple. The `.route()` calls in
# `synapse-web/src/routes/**` never mention them, so the extractor cannot infer
# them. The fields and their consumer surfaces today:
#
#   * `rate_limit_exempt` — 5 routes from sync.rs + sliding_sync.rs. When
#     `true`, the IP-level rate-limit middleware (`rate_limit.rs:35`) skips
#     the path. The list is auto-derived at startup by `assembly.rs:405`
#     scanning the ledger; deleting the manifests without first moving these
#     5 annotations into this table would silently drop the exemption and put
#     double-rate-limit on the sync endpoints.
#
#   * `auth` — 1 route from delayed_events.rs:128 (`.with_auth("user")`).
#     Exported into the ledger artifact by `ledger_export.rs:157`, which the
#     SDK contract-sync reads.
#
#   * `query_params` — the wire names of the axum `Query<Struct>` extractor the
#     route's handler deserializes, as a comma-joined, sorted, duplicate-free
#     list (`#[serde(rename)]` and `#[serde(alias)]` are both applied). A
#     dynamically typed extractor (`Query<Vec<(String, String)>>`,
#     `Query<HashMap<..>>`, `Query<Value>`) has no struct to enumerate, so it
#     is listed only when the handler — or a same-file helper it passes the
#     query to — compares string literals against the query key; that literal
#     set is the falsifiable evidence, never a guess.
#     Exported by `ledger_export.rs:156` and consumed downstream by
#     `scripts/api_test/gen_route_table.py` -> `docs/openapi/route-table.json`.
#     Guarded in *both* directions by `check_annotation_fidelity` in
#     `scripts/contract/extract_registered.py`: a declared name the handler does
#     not parse (or never compares a literal against) is RED, and a handler
#     with `Query<Struct>` fields or query-key literals but no annotation is
#     RED too. The committed ledger fixtures are the second, independent oracle.
#
#   * `body_opaque` — the route's JSON request body is protocol-arbitrary on
#     purpose (event content, account data, filters, room-key backups, UIA
#     `Value` bodies, federation PDUs/transactions, or a raw `Bytes` extractor
#     the handler parses with `serde_json::from_slice`/`from_str`), so there is
#     no addressable field list. Declaring it keeps the route out of the
#     "unknown body" debt. Guarded only in the positive direction by
#     `check_annotation_fidelity`: declaring it on a route whose handler body is
#     neither a bare `Json<Value>`/`MatrixJson<Value>` nor a `Bytes` +
#     manual-JSON-parse handler is RED. The unannotated remainder is a
#     counted ratchet (`EXPECTED_OPAQUE_UNANNOTATED`), so burning debt must
#     lower the pin while a *new* opaque body is RED.
#
#   * `unsupported` — the route is registered and reachable, but the documented
#     response is not implemented yet. Today this is exactly one endpoint: the
#     vendor `GET /rooms/{room_id}/keys/{event_id}` (C-1). It used to answer
#     200 with a placeholder `"keys": []`, which a client cannot distinguish
#     from "no keys"; it now answers 501 `M_UNKNOWN` so the gap is visible on
#     the wire instead of being disguised as success.
#
#   * `dynamic` — the `(method, path)` exists but the static extractor cannot
#     name a single handler definition, *by construction* rather than because
#     of a parser gap: `GET /` is served by the fallback chain. The 14
#     `app_service` proxy rows used to be listed here because `_handler_calls`
#     skipped `any(proxy_to_as)`; the extractor now expands `any(..)` to every
#     HTTP method, so those rows resolve to `proxy_to_as` and no longer belong
#     in this list.
#     Declaring it turns "static blind spot" into a finite, reviewable list:
#     `gen_route_handlers.py` requires `confidence: none` and `dynamic=true` to
#     be the *same* set in both directions, so a new blind spot (or a stale
#     declaration) is RED. It never asserts the handler is useless — the route
#     is still real and reachable at runtime.
#
# This table is the single source of truth for annotations, mirroring
# `ledger_origins.txt` for `registered_by`. Deleting a line and observing a RED
# fidelity test is the self-proof that the guard is real, not a tautology.
