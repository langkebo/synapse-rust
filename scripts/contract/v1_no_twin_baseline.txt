# 没有 v3 孪生的 `/_matrix/client/v1` 端点。
#
# 这一批**分三类**，都不是缺陷（逐条出处见 docs/audit/A3_v1_deprecation_strategy.md
# 的「2026-10-22 复核」与「2026-10-22 第三批」两节）：
#   A. MSC/规范把稳定前缀定为 v1 —— MSC3266 summary / MSC3856 threads / MSC3916 media /
#      MSC4108 rendezvous / MSC2965 auth_metadata / MSC2946 hierarchy / MSC3882 login token /
#      spec v1.6 timestamp_to_event / Matrix v1.11 media config；
#   B. MSC4512 的 AS 协议路径 —— proxy/*（7 方法）、appservice/fed_proxy。
#      ⚠️ 它们就该在 client/v1：治理文档 §13.24 的「移出客户端面」指的是**SDK 不封装**，
#      不是改 URL。别照那句话把它们挪到 vendor。
#   C. 真正的私有扩展 —— 目前只剩 config/client 1 条（无 MSC/规范出处）。
#      处置方向是 /_matrix/vendor/v1（ISSUE-13），但**没有回退路径**，须与客户端同步做。
#
# ⚠️ 曾把 login/{get_token,qr_token} 与 POST v1/sync 误归为私有扩展：前者是 MSC3882 家族、
#    后者是 sliding sync 的稳定路径族（治理文档 §13.5「规范多挂载（应保留）」）。
#
# 因此**不要**给这里任何一条补 v3 孪生：那是凭空扩大非标准 API 面，门禁会直接拦。
#
# 每消失一行都必须是刻意决定：先把替代路径（v3 双注册 / vendor 前缀）做实，
# 再在本文件里删掉该行并写清迁移依据。门禁两个方向都查：
#   * 真实路由里已不存在的条目 → 红（防止只删代码、忘删基线）；
#   * 真实路由里新出现、基线未登记的无孪生 v1 端点 → 红（防止退役面反弹）。
