# `stream_writers` 写归属映射 —— **冻结清单**（W-I）
#
# 三列：`METHOD <TAB> path <TAB> stream`
#
# `stream` 为空归属记作 `-`，意思是"这不是任何一路流的写"：登录、注册、设备管理
# 之外的账号面、E2EE 密钥、媒体上传、以及本服务自建的 space/thread/friend 表等
# （这些数据不在房间 DAG 里）。
#
# ⚠️ 这份清单是**双向棘轮**（`tests/unit/worker_write_stream_tests.rs`）：
#   1. 清单里的 (method, path) 必须与真实路由表 `declared_ledger_all()` 的写面
#      （客户端 + vendor + 联邦 + **管理面**）**完全一致** —— 新增一个写路由而不改这里，
#      测试红（逼你做"它属于哪一路流"的决定）；
#   2. 第三列必须与 `stream_for_write()` 的返回值一致
#      —— 代码里改了匹配规则而不改这里，同样红。
#   3. 一条流声明了哪些命名空间（`WriteStream::mapped_surfaces`），它的行就必须来自那些
#      命名空间 —— 给只映射客户端面的流加一行联邦面，同样红。
#
# 为什么需要它：`stream_for_write` 漏掉一条本该归流的写路由时，那一路就悄悄回到多写者状态，
# 而**没有任何运行期症状**。这份清单把"漏掉"变成一次提交时的失败。
#
# 归属判据（`synapse-services/src/worker/write_streams.rs` 的模块文档有完整版）：
#   * `events`       —— 写房间 DAG（create_event / send / state / redact / 成员变更），
#                        **或**向联邦对端广播房间级 PDU/EDU（sticky 元数据就是这一类）；
#   * `device_lists` —— 写 `device_lists_stream` / `device_lists_changes`
#                        （建设备、改设备名、删设备、改设备密钥/交叉签名），
#                        之后 `broadcast_device_list_update` 会给同房间的远端服务器发
#                        `m.device_list_update` EDU —— 重复就是重复广播。
#
# ⚠️ 棘轮的**盲区**：它比的是路由集合，不是 handler 行为。一条已经存在的路由**开始**
#    写事件（例如 `v1/invite` 将来补上落库），这份清单不会变红。改动那类 handler 时
#    必须回来重看这一列。

# ── 管理面（`/_synapse/admin/*`，C-S 之外的运营接口）─────────────────────────────
#
# 这个命名空间同样在 `declared_ledger_all()` 里（156 条写路由），所以**不需要**换账本
# 来源，直接逐条判归属即可。只有 **16 条**真的写受管流，其余 140 条记 `-`：它们改的是
# 服务端表（users / media / tokens / retention / room_directory / audit），不写房间 DAG、
# 也不写 `device_lists_stream`。
#
# 判据是读 handler 得来的（每条都追到 `create_event` / `upsert_power_levels_event` /
# `create_event_with_graph` / `revoke_device` / `logout_all`），**不是**按路径名猜：
#   * `events`（12）  —— ban×2 / kick×2 / unban / members PUT|DELETE / make_admin×2 /
#                      backfill / join / send_server_notice
#   * `device_lists`（4）—— 删设备两种拼写 / users/{u}/logout / user_sessions/{u}/invalidate
#
# ⚠️ 三条看着像、实际**不**归流的（已逐条核实，别再"顺手"加进来）：
#   * `POST /rooms/{id}/shutdown_room` —— 只 `UPDATE rooms SET is_public=false` + 清成员行，
#     不发事件、不广播（`synapse-storage/src/room/mod.rs:1023`）；
#   * `POST /users/{u}/evict` —— 逐房间调**存储层** `remove_member`，不是 `leave_room`，
#     所以不产生 `m.room.member`（`synapse-services/src/admin_user_service.rs:321`）；
#   * `PUT|DELETE /rooms/{id}/listings/public` —— 只改 `rooms.is_public` + `room_directory`
#     （`synapse-storage/src/room/admin.rs:417`），没有 `m.room.join_rules`。
#
